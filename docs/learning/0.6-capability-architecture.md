## The mental shift

I assumed an architecture with no technology in it would be vague. It is the opposite: with
nothing to hide behind, every arrow had to be a contract with a requirement number, and every
box had to say what it owns and emits. Drawing the daily-session flow that way *surfaced* an
architectural decision I would otherwise have met as a bug months from now — the pack is built
on last night's statuses, so a story can go stale by morning (charter R3). Naming it as a
Phase 5 question with three costed options is what the capability view is for. The technology
question ("which framework?") is genuinely secondary to "who owns `SkillMastery` and who is
allowed to read it".

## Gotchas hit

- The Mermaid CLI's first run downloads a headless browser; it took about two minutes. Started
  it in the background before writing the document, so it was ready when the document was.
- Without a filter, Pandoc puts **both** the PNG and the Mermaid source into the `.docx`. Added
  `drop-mermaid.lua` (five lines) and the `--lua-filter` flag; verified by reading the `.docx`
  back: five images, zero Mermaid code blocks.
- `autonumber` in a sequence diagram numbers messages, not the steps I had in my head: the
  daily-session table cited a step 14 that did not exist. Caught only by looking at the rendered
  PNG, not at the Markdown. Diagrams need a look, the same as documents need a read-back.
- Diagram labels are English/ASCII. Arabic inside Mermaid rendered by a headless browser is a
  font path I have not tested; the prose around the diagrams is bilingual, the diagrams are not.
  A risk avoided, not measured — worth one test before the pedagogy diagrams.
- `render-diagrams.py` writes a `.tmp/` scratch folder beside the documents (and the warm-up
  left `warmup.mmd`/`.png` there). Not staged; 0.7's `.gitignore` will exclude it.
- Committing with an explicit pathspec (`git commit -- paths`) left the IDE's staged
  `.gitignore` *untracked* afterwards rather than staged. Harmless here; worth knowing that a
  pathspec commit rewrites the index for what it commits and can drop other staged entries.

## Check yourself

1. The parent dashboard needs data from Learners (statuses) and from Tutor (plan reasons). Why
   may it not join their storage, and how does it get its data instead?
2. In the read-aloud flow, which step guarantees that a mumbling child is never marked wrong,
   and what does the request through the recognise port deliberately *not* contain?

<details><summary>Answers</summary>

1. Module rule 1: no module reads another's storage. The dashboard is a read model built from
   `MasteryChanged` / `SkillMastered` / `ConfusionDetected` and `SessionPlanned` events (or by
   calling each module's contract) — never by a query across their tables.
2. Step 8–10: the speech service applies the confidence floor and emits *no-evidence* rows for
   words below it; the learner model never lowers a mastery estimate on them (FR-LRN-006, G10).
   The port request carries audio and the target text only — no profile fields (FR-AI-004).

</details>
