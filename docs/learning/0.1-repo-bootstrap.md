## The mental shift

Wathiq's workflow was built to *ship* a stack I already knew; here the same workflow has to
*choose* a stack I don't know yet. That flips what a step proves. In Wathiq a step was done when
the code ran; in Nabta a study step is done when a **number** exists — a compliance rate, a word
error rate, a cost per child-day — and the note says what that number changes. The skills had to
be rewritten around that: `next-step` refuses a study step with an empty results table, and the
decisions log refuses an ADR without an experiment. The cadence is borrowed; the definition of
"done" is new.

## Gotchas hit

- `/next-step` does not exist until this step creates it, so 0.1 was run by hand from its
  ROADMAP definition. Every later step goes through the skill.
- Bash heredocs on this Windows/Git-Bash setup broke on files with mixed quotes (the same
  gotcha Wathiq's 0.1 note recorded). Files were written with the editor tool; the docs build
  script in 0.2 should be PowerShell for the same reason.
- A long design discussion preceded this step (the reference child ماسة, fifteen goals, the
  garden progress view, harakat as sub-skills, story kinds, a technology decision map). None of
  it is in the repo yet on purpose: it belongs to `vision` (0.3) and `pedagogy` (0.4), not to a
  bootstrap commit.
