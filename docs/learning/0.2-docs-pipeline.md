## The mental shift

A Word deliverable is a **build artefact**: the `.md` is what gets reviewed in a diff, the
template is code, and `out/*.docx` is compiled output that is regenerated, never hand-edited.
Nabta adds one twist Wathiq did not need: the documents will *quote text a child reads*, and
that text has rules of its own — full harakat, large type, one idea per paragraph, vertical room
for the marks. Giving that text its own style (`ChildText`) means a reviewer can find every
child-facing sample in a document in one pass, and a later change to how children's text should
look is one line in `make-reference.py`, not a hunt through twelve documents.

## Gotchas hit

- Two Arabic lines inside one `::: {custom-style="RTL"}` block with no blank line between them
  render as **one** paragraph (Pandoc treats a single newline as a soft break). For `ChildText`
  that would defeat "one idea per line" — every child-facing line needs its own paragraph, i.e.
  a blank line between lines. `smoke.md` does this; `/make-doc` should too.
- Running `build.ps1` from Git Bash needs `powershell -NoProfile -ExecutionPolicy Bypass -File`;
  the default execution policy on this machine blocks unsigned scripts.
- `PYTHONIOENCODING=utf-8` was set before printing Arabic from Python — applied preemptively
  from Wathiq's 0.2 note rather than hit again; the console here is still code page 1252.
- No Mermaid CLI installed. `render-diagrams.py` falls back to `npx -y`, whose first run
  downloads a headless browser; deferred to 0.6, and worth running once *before* that session.

## Check yourself

1. Why does `ChildText` need both a larger line spacing *and* a blank line between source lines?
2. Which file do you edit to change how child-facing text looks — `reference.docx` or something else?

<details><summary>Answers</summary>

1. Line spacing gives harakat vertical room so marks above one line don't collide with the line
   above; the blank line makes each sentence its own paragraph, otherwise Pandoc soft-breaks them
   into one paragraph and "one idea per line" is lost.
2. `make-reference.py` — `reference.docx` is generated from it and would be overwritten.

</details>
